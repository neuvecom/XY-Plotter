## XY-Plotter 付属資料の日本語ドキュメント化

### 実施内容

AliExpress で購入した XY プロッター（Drawing Bot）の付属資料が説明不足だったため、
付属物（組立写真・ファームウェア・APK・動画）を実際に解析し、日本語の実用ドキュメントを整備した。

調査した内容は以下のとおり。

1. **組立説明書 16 ページの読み取り**
   - `1.Installation instruction.pdf` は 16 ページ・画像 16 枚。
     `Backup/1.Installation instruction/01〜16.jpg` と 1 対 1 で同内容であることを確認。
   - 各ページの写真から使用部品・数量・手順を読み取った。

2. **配線の確定**
   - 公式配線図（11.jpg）の拡大読み取りと `Drawing.ino` の `attach()` を突き合わせ、
     サーボ A=D9（ペン昇降）/ B=D10 / C=D11、HC-06 は D0/D1 と確定。

3. **ファームウェアの解析**
   - 5 節平行リンクの逆運動学（余弦定理）であることを確認。
   - 機体寸法は `baselen=4.5 / arm1len=3.0 / arm2len=6.0`（cm）。
   - 受信値の単位は 1/50 cm = 0.2 mm、原点は肩の中点から 30 mm 上。
   - 起動時のサーボ角 120°/60° が座標 (0,0) に対応することを計算で確認。

4. **APK の解析**
   - パッケージ `com.ai2offline.test.Minidrawing3` / v1.01 / MIT App Inventor 2 製。
   - 要求権限は BLUETOOTH 系 4 つ + READ_EXTERNAL_STORAGE。位置情報は要求しない
     （= OS でペアリング済みの一覧を使う実装）。
   - UI 部品は `BTpickbutton`(Bluetooth) / `Canvas1` / `btn_redraw` / `btn_clear` / `Label1` / ESC ボタン。
   - `Clock1$Timer` が Arduino からの `"N"` を待って次の点を送るフロー制御になっている。

5. **プロトコルの確定**
   - 書式 `X,Y,P,R`（カンマ 3 個が必須）、応答は `N` 1 文字。
   - ファーム側パーサと APK 側の文字列生成の両方から裏を取った。

6. **付属動画が別製品であることの発見**
   - `App use video/*.mov` 2 本は「RA示教器 / Robot Arm 四軸機械臂示教器 V1.01」という
     **別製品（4 軸ロボットアーム）のティーチングアプリ**を映していた。
   - Bluetooth のペアリング手順部分のみ流用可能。アプリ画面は本製品と無関係。

### 検証

- **ファームウェアの等価性**
  Arduino API の最小シムを用意し、公式版と日本語コメント版を g++ でビルドして
  同一のコマンド列（到達可能／不能、ペン上下、両補間分岐、異常入力を含む 14 コマンド）を
  1 バイトずつ流し込み、`Servo.write()` の全値とシリアル送信を比較。

  ```
  $ python3 tools/equivalence_check/run.py
  [OK] 公式版と日本語コメント版の動作は完全に一致しました（1685 件の操作を比較）
  ```

  ※ AVR 実機ビルドではなく、ロジック同一性の検証。

- **描画可能範囲**
  `tools/workspace_map.py` でファームの計算式を移植し総当たり。
  最大幅は Y=20 のとき X=−259〜+259（103.6 mm）、Y の上限は 285 付近。
  実用目安として X: ±240 / Y: 20〜200（約 96 × 36 mm）を提示した。

- **APK の同一性**
  `official-manual/APP_Drawing Bot.apk` と `Backup/APP_Drawing Bot.zip` 内の APK が
  同一ファイルであることを確認（SHA-256: `70143a2c...4e896`）。

### 未確認・今後の課題

- **DC ジャックの推奨電圧が不明**。付属資料に記載がなく、実機も手元にないため確認できなかった。
  ドキュメントには「不明」と明記し、USB 給電を推奨する形にした。
- 肩サーボ B / C のどちらがコード上の `servo1` / `servo2` かは、公式写真からは
  左右の断定ができなかった。「図形が左右反転したら D10 と D11 を入れ替える」という
  対処法を [07](../manual/07-calibration-and-troubleshooting.md) に記載して回避した。
- アプリの座標変換係数（キャンバス座標 → 機械座標）は APK 解析では定数まで特定できなかった。
  実機で送信内容をモニタすれば確定できる。
